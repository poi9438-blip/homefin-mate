### CI 첫 실행

PR에서 처음 실행했을 때 **명세 대조 job(`test-case-status`)이 실패**했습니다. 세 모듈의 결과 파일은 정상적으로 내려받았습니다.

- **원인 (테스트 코드 문제):** 커밋 과정에서 `RiskWatchClientAuditTest`가 ID를 붙이기 전 버전으로 돌아가 `[TC-RISK-008]`, `[TC-RISK-009]`가 빠졌습니다. 그래서 명세에는 있는데 테스트가 없는 상태("확인 필요: 테스트 없음")가 됐습니다.
- **조치:** ID를 다시 붙이고 로컬에서 `tc_status.py --strict` 통과를 확인했습니다. 또 결과 표를 Summary에만 쓰던 것을 로그에도 남기게 바꿨습니다. 처음에는 로그에 원인이 보이지 않았기 때문입니다.
- 명세와 코드가 어긋나는 것을 CI가 실제로 막아 낸 첫 사례입니다.

## 5. 테스트가 실제로 결함을 잡는지 확인 (변이 검사)

처음부터 통과한 테스트는 결함이 있어도 통과하는 테스트일 수 있습니다. 그래서 제품 코드를 일부러 틀리게 바꿔 실행했습니다.

- 매번 `target`을 지우고 다시 빌드했습니다.
- 확인 후 `git checkout`으로 되돌렸습니다.

| 변이                                            | 실패한 테스트                           | 판정                                      |
| ----------------------------------------------- | --------------------------------------- | ----------------------------------------- |
| M1 URL 규칙의 관리자 제한을 `authenticated()`로 | TC-AUTH-103 (4건)                       | 잡음. 단 응답이 400 → **#84 발견** (아래) |
| M1b M1 + `@PreAuthorize` 제거                   | TC-AUTH-103 (4건, 200 응답)             | 잡음                                      |
| M2 계산 이력을 사용자 구분 없이 전체 조회       | TC-DATA-101, 102                        | 잡음                                      |
| M3 월 이율을 ÷1000으로                          | 계산 테스트 10건 (TC-LOAN-202 5건 포함) | 잡음                                      |
| M4 `Bearer ` 없는 토큰도 인정                   | TC-AUTH-108                             | 잡음                                      |
| W1 axios 401 처리를 403으로                     | TC-WEB-205                              | 잡음                                      |
| W2 로그아웃 시 사용자 정보 삭제 제거            | TC-WEB-201                              | 잡음                                      |

**검사 중 실수:** M4를 처음 적용할 때 잘못된 코드를 넣었습니다. 그 컴파일 결과가 `target`에 남아서 다음 실행들이 서버 시작 실패로 전부 실패했습니다. 결함을 잡은 것으로 잘못 읽을 수 있는 결과라 버리고, 깨끗한 빌드로 다시 측정한 값이 위 표입니다. 이 일로 [TESTING.md](TESTING.md) 6번에 "`target`을 지우고 다시 빌드" 규칙을 추가했습니다.
