# 인증 · 인가 (TC-AUTH)

대상: `AuthService`, `AuthController`, `JwtUtil`, `JwtAuthFilter`, `SecurityConfig`, `AuthCookies`

- **토큰 전달 (#78, 2026-10-26):** 로그인 성공 시 토큰은 `hfm_session` 쿠키(HttpOnly, Secure, SameSite=Strict, Path=/api)로만 보내고 응답 본문에는 없습니다. 화면은 본문의 `expiresAt`(토큰 exp)만 저장합니다.
- **인증 방법:** `Authorization: Bearer` 헤더(테스트·k6·서비스 간 호출) 또는 `hfm_session` 쿠키(브라우저). 둘 다 있으면 헤더가 우선입니다.
- **CSRF:** 쿠키로 인증하는 상태 변경 요청(POST 등)은 `XSRF-TOKEN` 쿠키와 같은 값의 `X-XSRF-TOKEN` 헤더가 있어야 합니다(이중 제출). Bearer 헤더 요청은 대상이 아닙니다.
- **로그아웃:** 서버가 `hfm_session`을 `Max-Age=0`으로 지웁니다. 토큰 자체는 서명 기반이라 만료 전까지 유효합니다(#92).

- **공개 주소:** `/api/auth/**`, `/api/policy/**`, `/api/analysis/**`, `/api/loan/dti`, `/actuator/health`, Swagger(`SWAGGER_ENABLED=true`일 때만 켜짐)
- **역할:** 토큰은 이메일만 증명하고, 역할은 요청마다 DB(users)에서 읽습니다 (#44).
- **관리자 전용:** `/api/admin/**`
  - URL 규칙과 `AdminController`의 `@PreAuthorize`가 이중으로 막습니다.
- **나머지 주소:** 로그인이 필요합니다.
