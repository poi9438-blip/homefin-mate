# 외부 연동 · 통합 분석 (TC-RISK, TC-REGION, TC-ANLZ, TC-FULL)

| 대상                    | 내용                                                                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `RiskWatchClient`       | 위험 평가 호출. 연결 1초·응답 2초 타임아웃, 5xx·연결 실패만 재시도, 실패하면 감사 기록 + fallback(`available=false`)                     |
| `AnalysisService`       | Python 지역 분석 호출. 한글 지역은 URL 인코딩, Python의 snake_case를 읽음. 없는 지역(404)·연결 실패면 숫자 없이 `available=false` + 이유 |
| Python `python-service` | `GET /analysis/region`. 출처 없는 예시 시세 (#39)                                                                                        |
| `AnalyzeService`        | 계산·정책·위험·지역을 저장 없이 실행한 뒤 `AnalyzeResultSaver`가 **한 트랜잭션으로** 저장 (#5 수정, 외부 호출은 트랜잭션 밖)             |

- **RiskWatch는 별도 저장소(riskwatch-system)입니다.** 자동 테스트의 정상 응답은 MockRestServiceServer로 만들고, 실제 RiskWatch와의 연결(서비스 토큰·판정)은 두 서비스를 Docker로 함께 띄워 확인합니다.
- **위험 평가는 추천 상품 하나로만 요청합니다(RiskWatch 4단계).** 추천 상품이 없거나 주택 보유·2년 내 출산·맞벌이 입력이 없거나 RiskWatch 입력 범위 밖이면 부르지 않고 `NOT_EVALUATED`와 이유를 돌려줍니다. 그래서 RiskWatch 장애를 보는 테스트(TC-ANLZ-101, k6 S1·S2)는 추천 상품이 나오는 입력(주택 가격 6억 원 → 보금자리론)을 씁니다.
- **통합 테스트는 외부 주소를 닫힌 포트(`127.0.0.1:9`)로 바꿔서 실행합니다**(`application-test.yml`). PC에 Docker 서비스가 떠 있는지와 관계없이 결과가 같게 하기 위해서입니다.
