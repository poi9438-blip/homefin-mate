## ID 규칙

`TC-<영역>-<번호 3자리>`. 번호 앞자리는 테스트가 생긴 경위를 나타냅니다.

| 번호 | 뜻                                                             |
| ---- | -------------------------------------------------------------- |
| 0xx  | 품질 체계를 만들기 전부터 있던 테스트                          |
| 1xx  | HTTP 통합 테스트 (보안 필터·DB 포함, `@SpringBootTest`)        |
| 2xx  | 단위 테스트 (추가분)                                           |
| 3xx  | 아직 테스트가 없는 항목. `작성 예정` 또는 `자동화 안 함: 사유` |

한 번 쓴 ID는 지우거나 다른 테스트에 다시 쓰지 않습니다. 테스트를 없애면 행에 "폐기"와 사유를 남깁니다.

## 표 형식

| 열        | 내용                                                                |
| --------- | ------------------------------------------------------------------- |
| ID        | 위 규칙                                                             |
| 분류      | 정상 / 예외 / 경계 / 보안                                           |
| 확인 내용 | 목적과 입력(사전 조건 포함)                                         |
| 기대 결과 | 요구사항 기준 기대 결과. ⚠️는 **현재 동작을 고정**한 것 (아래 참고) |
| 위험      | P0~P3 ([테스트 기준](../TESTING.md#9-우선순위와-위험도))            |
| 자동화    | 테스트 위치, 또는 `자동화 안 함: 사유`                              |
| 관련      | 알려진 문제 번호, 요구사항 확인이 필요하면 `확인 필요`              |

**실행 결과는 이 문서에 손으로 적지 않습니다.** 결과는 매번 바뀌어서 손으로 적으면 금방 틀립니다.
테스트를 실행한 뒤 아래 스크립트가 명세, 테스트 코드, 결과 XML을 대조해서 보여 줍니다.

```bash
python scripts/tc_status.py            # 표로 보기
python scripts/tc_status.py --strict   # 불일치·실패·미실행이 있으면 종료 코드 1
```

결과는 `통과` / `실패` / `미실행`(결과 XML 없음) / `작성 예정` / `자동화 안 함` / `확인 필요`(명세와 코드 중 한쪽이 없음) 중 하나입니다.

## ⚠️ 현재 동작 고정

결함인 동작을 "지금은 이렇게 동작한다"로 단언한 테스트입니다. 이름과 표에 ⚠️와 문제 번호를 붙입니다.

- 결함이 언제 고쳐졌는지(또는 의도치 않게 바뀌었는지) 테스트 실패로 바로 알 수 있습니다.
- 문제를 고치는 PR에서 기대 결과를 올바른 동작으로 **뒤집고** ⚠️를 뗍니다. 테스트를 지우지 않습니다.
- 사소하고 고치는 방법이 분명한 결함은 테스트 없이 3xx 행과 알려진 문제에만 적습니다.
