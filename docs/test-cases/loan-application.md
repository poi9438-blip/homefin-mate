# 대출 신청 · FinFlow 연결 (TC-APPLY)

대상: 통합 분석 결과의 추천 상품으로 FinFlow에 대출 신청, 내 신청 목록·취소 (`/api/applications`, FinFlow 신청 API)

- **HomeFin이 저장하는 것은 신청 번호뿐입니다** (`user_applications`: 사용자, FinFlow 신청 번호, 상품, 계산 기록 id, 시각). 신청 상태의 기준은 FinFlow 하나라서, 목록을 볼 때마다 FinFlow에서 상태를 가져옵니다.
- **서버가 다시 계산합니다.** 신청 요청에는 통합 분석과 같은 입력과 상품 코드를 받고, 서버가 DTI와 상품 판정을 다시 해서 그 상품이 "충족"일 때만 FinFlow에 보냅니다. 화면이 보낸 값으로 판정하지 않습니다.
- **같은 신청을 두 번 보내도 하나만 생깁니다.** 화면이 버튼을 누를 때 만든 `Idempotency-Key`를 그대로 FinFlow에 보내고, FinFlow는 같은 키를 처음 결과로 돌려줍니다. 그래서 HomeFin은 FinFlow 응답을 못 받았을 때(시간 초과 포함) **같은 키로** 다시 보내도 됩니다.
- **관점:** 정상(신청·목록·취소), 예외(FinFlow 장애·거절, 충족하지 않는 상품, 빠진 입력), 경계(같은 키 재전송, 재시도 횟수), 보안(다른 사용자의 계산 기록·신청, 서비스 토큰, 비밀키 분리)을 봅니다.
- 구현보다 먼저 쓰고 구현과 함께 자동화했습니다. HTTP 통합 테스트는 FinFlow 전용 RestTemplate에 MockRestServiceServer를 붙여 FinFlow 응답을 대신합니다. 실제 FinFlow와의 연결은 세 서비스 통합 compose로 확인합니다(TC-FULL).
